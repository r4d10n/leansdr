================================================================================
BUILD OPTIONS
================================================================================

Via Makefile:
  make bench-build          # Build both scalar and NEON versions
  make bench-run            # Build and run with full report
  make bench-all            # Same as bench-run

Manual build:
  # Scalar (any platform)
  g++ -O3 -I../src benchmark_neon.cc -o benchmark_neon_scalar

  # NEON (ARM only)
  # For ARMv7:
  g++ -O3 -march=armv7-a -mfpu=neon -ftree-vectorize \
      -I../src benchmark_neon.cc -o benchmark_neon_neon

  # For ARMv8/AArch64:
  g++ -O3 -march=armv8-a -ftree-vectorize \
      -I../src benchmark_neon.cc -o benchmark_neon_neon

================================================================================
INTERPRETING RESULTS
================================================================================

CSV Format:
  operation,param1,param2,scalar_cycles,neon_cycles,speedup

Example:
  fir_filter,128,1024,194937,51234,3.80

Means:
  - Operation: FIR filter
  - Param1: 128 filter taps
  - Param2: 1024 samples processed
  - Scalar: 194,937 CPU cycles
  - NEON: 51,234 CPU cycles
  - Speedup: 3.80x faster with NEON

Speedup Guide:
  >4.0x   = Excellent (approaching theoretical max)
  2-4x    = Good (typical for well-vectorized code)
  1.5-2x  = Moderate (some benefit, but overhead limits gains)
  <1.5x   = Limited (memory-bound or complex dependencies)

================================================================================
TROUBLESHOOTING
================================================================================

Problem: Speedup is 1.0x (no improvement)
Solution:
  - Check you're on ARM: uname -m
  - Check NEON support: grep -i neon /proc/cpuinfo
  - Verify NEON instructions: objdump -d benchmark_neon_neon | grep vmla

Problem: Lower speedup than expected
Solution:
  - Disable CPU frequency scaling: sudo cpupower frequency-set -g performance
  - Check thermal throttling: vcgencmd measure_temp (RPi)
  - Close background applications
  - Try smaller data sizes to stay in L1 cache

Problem: Build errors
Solution:
  - Missing compiler: sudo apt-get install g++
  - ARM only: Ensure using ARM compiler with NEON flags
  - x86: Can only build scalar version (expected)

================================================================================
ADVANCED USAGE
================================================================================

Run specific benchmark manually:
  ./benchmark_neon_neon 2>&1 | grep "fir_filter"

Compare multiple runs:
  for i in 1 2 3; do
    ./benchmark_neon_neon > run_$i.csv
  done
  # Compare run_*.csv files

Profile with perf (Linux):
  perf record -g ./benchmark_neon_neon
  perf report

Check NEON instruction usage:
  objdump -d benchmark_neon_neon | grep -E 'vmla|vadd|vmul|vld|vst' | wc -l

Cross-compile for ARM (from x86):
  arm-linux-gnueabihf-g++ -O3 -march=armv7-a -mfpu=neon \
    -I../src benchmark_neon.cc -o benchmark_neon_arm
